## How the assets are produced

- The generator is pure Node.js (ESM) with **zero dependencies**: it contains its
  own PNG encoder (IHDR/IDAT/IEND chunks + a local CRC32 table on top of
  `node:zlib`), its own IHDR reader (used by `--verify`), and hand-rolled
  drawing primitives (rect/ellipse/polygon fills, lines and curves, noise
  dithering, outlines, top-left lighting helpers).
- All randomness comes from a **fixed-seed mulberry32 PRNG**, with per-file
  sub-seeds derived by hashing each file's relative path. `Math.random()` is
  never used, so re-running the generator produces **byte-identical** files
  on any machine.
- Pixel dimensions, folder layout and spritesheet layout are dictated by
  [`src/assets/assetManifest.ts`](../src/assets/assetManifest.ts); the script
  keeps a mirrored dimension table (with a comment saying so) and refuses to
  run if the table and the script's own drawing specs disagree.
- **No third-party art was copied, embedded, traced or converted.** The
  flat-shaded, top-down, lightly-outlined look is an original implementation;
  it takes *stylistic inspiration only* from general public-domain /
  CC0 pixel-art conventions such as Kenney's CC0 asset packs — no Kenney
  (or any other) files, tiles or sprites are present in this repository.

## How to regenerate

```sh
npm run assets          # == node scripts/generate-assets.mjs
npm run assets -- --verify   # re-read every IHDR and check sizes (exit ≠ 0 on mismatch)
```

Regeneration is deterministic: the same seed always produces byte-identical
files, so a regenerated tree should show no diff unless `MASTER_SEED` or the
drawing code changed.

## Third-party code note

The PNG encoder/decoder, CRC32 table, PRNG and all drawing helpers are
implemented inside `scripts/generate-assets.mjs` itself (no copied library
code); `node:zlib` — a Node.js built-in — is the only compression used.
